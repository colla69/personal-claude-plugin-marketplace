# Write a CV

A CV has two readers. A keyword search — an applicant tracking system (ATS), a
recruiter's database — reads every word literally. A person skims for eight seconds.
Every line has to work for both.

## Before you write

Read the CV as it stands, and its other language versions if there are any. Change only
the part you were asked about. A rewrite of the whole document destroys choices you
cannot see.

Every fact comes from the owner. Never invent a date, an employer, a number, a
technology or a scope. If the document needs a fact you do not have, ask for it, or
leave a visible note for the owner. Fill in the wording, never the facts.

## For the search

- A skill counts when a machine finds it in context. A term in the skills list and
  nowhere else is a claim. The same term in the project paragraph that used it is
  evidence. Put the load-bearing terms in both.
- Spell out both forms of anything with an alias: `Kubernetes (K8s)`,
  `continuous integration and delivery (CI/CD)`. Searches are literal.
- The header line and the profile hold the job titles the owner wants to be found
  under, in the words a hiring manager would type. Never an invented title.
- Keep the file plain: no tables, no columns, no text inside images, in any version a
  machine may parse.

## For the person

- Each project entry answers four things, in this order: what business problem, what
  the owner owned, what stack, what it produced. Anything else is padding.
- Verbs carry seniority, so keep them exact. *Built*, *owned*, *led* and *advised* are
  four different claims. Never use a stronger verb than the facts support.
- A CV with no numbers is weak. Aim for one figure per project that the owner can
  defend — users, transactions, build time saved, release frequency. Ask for it. Never
  estimate it.
- The last sentence of the profile is the only line that looks forward. A hiring
  manager reads it to decide fit. Treat it as the most important sentence on the page.
- Cut what earns nothing: skills nobody will ask about, old low-level language
  certificates next to a claim of fluency, and — on a public page — birth date, marital
  status and home address.

## Tailoring to a job ad

Mirror the ad's vocabulary where it is honestly the same thing. Reorder the skills so
the ad's stack leads. Rewrite the closing sentence of the profile for that role. Write
the result to a new file, and keep the master as the full record.

Never invent experience to close a gap. Name the gap, so the owner can decide whether
to apply anyway.

## Where this yields

- To the owner's own wording, where it is plain and accurate.
- To the conventions of the CV's country and language — length, photo, personal data —
  where they differ from what is written here.
- To `work-discipline` on scope: change what was asked, and say what you left.
